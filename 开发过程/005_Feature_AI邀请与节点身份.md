# 005 Feature - AI 邀请与节点身份

## 背景

旧式 Agent 接入只给用户一串长期 Token，无法表达它属于谁、如何安全交付、如何恢复未知结果，也不能形成可单独撤销的运行节点身份。Phase 4 的目标是完成“人类控制者创建 AI Card -> Agent 本机持钥认领 -> 页面显示连接 -> 控制者撤销”的最小闭环。

## 关键决策

- 创建邀请时即创建永久 AI Card；认领只绑定节点，避免超时重试制造重复身份。
- 中文昵称用于展示，唯一 `@handle` 用于提及，机器名使用受限 ASCII，永久 Card ID 和内部 Principal ID 不混用。
- 邀请票据和认领查询秘密均为 256-bit 随机值，服务端只保存 SHA-256 哈希。
- Agent 使用 Ed25519 私钥签署规范化认领载荷，私钥只保存在 Agent 本机。
- 认领 ID 加查询秘密用于安全恢复未知结果；同一认领 ID 返回同一节点，不重复注册。
- 同一 AI Card 可以追加独立节点；邀请和节点分别撤销，不影响 Card 或其他节点。
- 节点“已连接”来自签名认领或一次性 challenge 认证，不接受客户端自报在线。

## 否掉的备选

- 认领成功后才创建 Card：网络超时会把身份创建和幂等恢复耦合，重复身份风险更高。
- 网页直接生成或保管 Agent 私钥：扩大服务端秘密面，违背节点独立持钥边界。
- 用一个长期主 Token 连接所有节点：无法单独撤销，也无法证明哪个运行环境在使用身份。
- 只用认领 ID 查询结果：可被枚举；必须同时提供独立查询秘密。

## 实现范围

- Forward-only migration `0004_agent_enrollment.sql`。
- 邀请创建/撤销、签名认领、状态恢复、节点 challenge/authenticate、节点撤销 API。
- 私有 Card 背面的 AI 身份控制面板和一次性完整指令。
- 从标准输入读取邀请、在本机生成并落盘节点凭据的参考 Agent。
- 桌面与移动端端到端闭环和数据库安全边界测试。
- 未新增第三方依赖；Ed25519 使用 Node.js 内置 `crypto`。

## 状态与失败路径

- 邀请：等待认领、已认领、已过期、已撤销。
- 节点：已连接、离线、已撤销。
- 重复票据、错误签名、错误查询秘密、过期/撤销邀请、重复 challenge 和撤销节点均明确失败。
- 指令只在创建成功后显示一次；刷新后不能从服务端重新获取票据。

## 验证结果

- 单元测试：15 个文件、43 项通过。
- 集成测试：5 个文件、20 项通过，使用隔离 PostgreSQL 17 和完整 migration。
- Agent 专项 E2E：桌面/移动端 2 项通过。
- 全量 E2E：24 项通过，覆盖原有四态、公开 Card、Passkey 和视觉基线。
- `npm run verify` 从头通过：lint、类型检查、生产构建、单元、集成和全量 E2E 全部成功。

## 影响范围

- 新增 AI Card 身份和节点表，不修改既有 migration checksum。
- 私有 Card 页面新增 AI 身份控制面板；公开 Card 投影和 Yoyoo 不变。
- 新增匿名 Agent 协议端点，但需要票据、查询秘密或 Ed25519 签名，并受速率限制。
- 当前仍无平台授权、账号恢复、独立安全验收和生产部署，不可对外宣称生产就绪。
